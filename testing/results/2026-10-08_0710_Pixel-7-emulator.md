## Why Build APK failed (link stage; compilation now gets through)

1. **zlib not linked.** `libid3tag.a` (`util.c:135`, `id3_util_decompress`) references `uncompress`,
   `inflateInit_`, `inflate`, `inflateEnd`, `compress2`. Both ABIs. `libmixxx_*.so` needs `-lz`
   (e.g. `ZLIB::ZLIB` / `z`) after libid3tag.
2. **NDK mismatch in a cached dependency (arm64 only).** `libsleefdft.a` (`dftcommon.cpp.o`) was built with
   **NDK 30.0.16248370** headers (`__string/char_traits.h:534`), but the app links with **NDK 29.0.14206865**:
   `undefined symbol: std::__ndk1::__hash_memory(void const*, unsigned long)`. The vcpkg binary cache for
   arm64-android has to be rebuilt with the same NDK as the app (or the NDK pinned in both jobs).

Previous runs: 37729129514 cancelled, 37727519791 and 37724479852 failed.

## Notes on tools/android/phone_test.sh (not changed; found while testing)

- `gh run list -w Android` finds nothing: GitHub lists the workflow as **"Android CI"**
  (`gh workflow list`), although `android.yml` says `name: Android`. The script would report
  "No successful Android CI run" even after a green build.
- On an Apple Silicon Mac the emulator is **arm64-v8a**, not x86_64; the script picks the arm64 APK by ABI,
  which is correct.
- With a real phone also on USB, plain `adb` fails ("more than one device"); `ANDROID_SERIAL=emulator-5554`
  works without changes to the script.
