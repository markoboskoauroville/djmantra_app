## Summary for the mapping

| Group | Messages |
|---|---|
| Channels | global `90`/`B0`, global+SHIFT `93`/`B3`; deck 1 `91`/`B1`, deck 2 `92`/`B2`; deck SHIFT layer `94`/`B4`, `95`/`B5`; pads `96` (deck 1), `97` (deck 2) |
| SHIFT | **one per deck**: `91 04` / `92 04` (7F press, 00 release) |
| Buttons | press `7F`, release `00` (note-on with velocity 0) |
| Knobs and faders | **all 14-bit**: MSB on CC n, LSB on CC n+0x20. Deck: volume `00`, filter `01` (centre 64), EQ low `02`, mid `03`, high `04`, tempo `08`. Global: crossfader `B0 00`, master `B0 03` |
| GAIN | SHIFT + HIGH sends **`B4 04`/`B4 24`** (deck 2 `B5 04`/`B5 24`): a separate CC on the SHIFT channel, so gain and high EQ are independent |
| Browser | turn `B0 01`: `01` = clockwise, `7F` = counter-clockwise (one message per click); SHIFT + turn `B3 01`; press `90 00`, SHIFT + press `93 00` |
| STEMS / centre N | `90 01`; SHIFT `93 01` |
| Jog | touch `91 08` / `92 08` (SHIFT `94 08`); **top** turn `B1 0A` / `B2 0A`, **outer ring** `B1 09` / `B2 09`; always ±1 per tick (`01` clockwise, `7F` counter-clockwise); about **240 ticks per revolution** (one turn: 236–248 messages). SHIFT + top: `B5 0A` on deck 2 (deck 1's SHIFT turn came in as `B1 0A`: SHIFT was probably not held, check). The ring is hard to touch without the top: ring steps also carry many `0A` ticks |
| Mode buttons | HOT CUE `0F`, LOOP `10`, FX `11`, NEURAL MIX `12` on the deck channel; **with SHIFT they send other notes on the same channel**: PITCH PLAY `13`, BOUNCE LOOP `14`, SLICER `15`, SAMPLER `16` (not `94 0F…`) |
| Pads | the controller switches pad mode itself; the note encodes mode and pad: **base + pad (0–7), +8 with SHIFT**. Bases: HOT CUE `00`, LOOP `10`, FX `20`, NEURAL MIX `30`, PITCH PLAY `40`, BOUNCE LOOP `50`, SLICER `60`, SAMPLER `70` (table below) |
| LOAD | buttons 1 and 2 at the top: `91 0D` / `92 0D`; SHIFT `94 0D` / `95 0D` |
| PFL (headphones 1/2) | `91 0C` / `92 0C`; SHIFT `94 0C` / `95 0C` |
| Init | `B0 7F 7F` → the controller sends every knob and fader position (28 messages, 14-bit pairs). On USB connect it sends **nothing** by itself (12 s watched; the port opened ~0.5 s after USB enumeration). `B0 7F 00` does **not** clear the mode LEDs and pad-mode lights: they belong to the firmware. After power-on the firmware is in HOT CUE mode (HOT CUE bright, LOOP dim, pad 1 lit) |

- **Pads**: only notes `30`–`37` on `96`/`97` light the pads in the state the controller was in (NEURAL MIX mode was active).
  The colour is **cyan for every value** 01–7F (`01 03 10 12 1C 1F 40 42 60 74 7C 7E 7F` tried on pad 1, photo strip
  `leds/pad1_values_strip.jpg`): the velocity does not choose a colour, and `00` turns the pad off. Probably the pads answer
  only the active mode's notes and each mode has its own firmware colour: to be checked per mode.
- **Mode LEDs latch**: lit by firmware when a mode is chosen; a software `00` does not override them for long.
- `90 01` lights the centre N logo (white). `93`: nothing. Deck 2 HOT CUE (`92 0F`) showed no change only because it was already lit.
- No message reached the battery LED.

## Problems found / suggestions for the cloud session

1. **The APK still crashes at start on both devices: `libomp.so` is not packaged** (`libmixxx_arm64-v8a.so` NEEDED `libomp.so`). Run #21 and the newer run 37762954016 (`8b9e4b8`) both. Link OpenMP statically (`-fopenmp -static-openmp`) or add the NDK's `libomp.so` to the APK's extra libs. Until then no library feature (rating, Export column, export menu) can be tested.
2. Signing is fixed: the APK installs (signer "DJ Mantra test builds").
3. Mapping: use the summary table above; the Mix Ultra is **not** the MIX layout for pads (8 pads, 8 modes, SHIFT+8) and mode buttons (SHIFT = notes 13–16 on the deck channel). Jog: 240 ticks per turn, ±1.
4. Pad LEDs: colour comes from the firmware/mode, not from velocity (in NEURAL MIX mode). Test pad LED notes per mode when the app can run.
5. Two steps to re-check on the real unit: deck 1 SHIFT + jog (`B4 0A` expected, `B1 0A` captured) and deck 1 EQ HIGH reached only 0–63 on the MSB (turned half way; the CC is right).
6. `tools/android/phone_test.sh` now finds runs by `android.yml` (fixed). With a real phone and the emulator both connected, plain `adb` fails: `ANDROID_SERIAL` was used.
7. **USB sticks on a Pixel are not plain files.** The stick mounted with `mountFlags=0` (not visible): it is only at
   `/mnt/media_rw/<id>`, which apps cannot read, and there is no `/storage/<id>`. "All files access" will probably not
   reach it. Plan the drive path through the Storage Access Framework (`ACTION_OPEN_DOCUMENT_TREE` on the stick, a
   persisted tree URI, reading through `ContentResolver` / `DocumentFile`), and copy into the track cache from there.
   The VolumeWatcher should watch `StorageManager` volumes (`StorageVolume`, `getStorageVolumes()`), not `/storage`.
8. Android MIDI (M5): the USB path will be `MidiManager` device type 1 named "Guillemot Corporation DJControl Mix Ultra";
   Bluetooth advertises as "DJControl Mix Ultra" (scan for the BLE MIDI service and `openBluetoothDevice()`, no pairing).
9. Mapping tool for the next controllers: **Controller Mapper (Mantra)** (repo markoboskoauroville/mix-ultra-mapper):
   a layout file per controller, the owner records every control in one sitting, the capture comes back in this format.
